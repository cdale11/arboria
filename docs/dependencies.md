# Dependency and lock policy

Status: R1 dependency baseline. This document records the supported toolchain currently installed in `arboria`; it does not mean the game is runnable.

## Supported platform

- Linux x86-64 on the inspected local host.
- Conda 26.3.2 with the default `pkgs/main` and `pkgs/r` channels.
- Existing environment name: `arboria`.
- No pip dependencies are authorized.
- Browser dependencies are pinned in `web/package-lock.json` and installed with npm inside activated `arboria`.

## Human-readable specs

- `environment.yml`: direct Conda requirements only.
- `web/package.json`: direct browser/build/test requirements only.

## Resolved locks

- `conda-linux-64.lock`: explicit Conda package URLs for Linux x86-64, generated from the installed `arboria` environment.
- `web/package-lock.json`: npm transitive dependency lock generated by npm from Node installed through Conda.

## Selected direct Conda dependencies

| Package | Role |
| --- | --- |
| `python=3.13` | Supported runtime selected because Python 3.14 compatibility was unverified and R1 required resolution |
| `numpy` | Authoritative numerical arrays and compact biological/learning kernels |
| `numba` | Optional compiled hot loops after profiling, not a mandatory biology dependency |
| `fastapi`, `uvicorn` | Local web API and static frontend serving |
| `pytest`, `hypothesis` | Unit, property, scenario, persistence, and regression tests |
| `mypy`, `ruff` | Python type and lint gates |
| `nodejs` | Environment-local TypeScript/frontend build runtime and npm |

## Selected browser dependencies

| Package | Role |
| --- | --- |
| `vite` | Browser build/dev tooling |
| `three` | Procedural 2.5D nursery rendering |
| `typescript` | Typed browser application code |
| `vitest`, `jsdom` | Frontend unit tests |
| `@vitejs/plugin-basic-ssl` | Future local HTTPS testing support; not a production TLS solution |
| `@types/node`, `@types/three` | Type declarations |

No browser e2e package is selected yet. `web/package.json` intentionally contains a failing `test:e2e` placeholder command so a later agent cannot accidentally claim the R1 browser e2e gate passed before implementation. Selecting browser automation is a separate R1 roadmap task because native browser dependencies must remain compatible with the Conda/npm policy.

## Regeneration commands

Run from the repository root in activated `arboria`:

```bash
conda env update -n arboria -f environment.yml --prune
conda list --explicit > conda-linux-64.lock
npm --prefix web install --package-lock-only
npm --prefix web ci
```

Because this development machine also has an NVM Node installation earlier in the inherited shell `PATH`, Node/npm commands must be run with the Conda prefix first:

```bash
PATH="$CONDA_PREFIX/bin:$PATH" npm --prefix web install --package-lock-only
PATH="$CONDA_PREFIX/bin:$PATH" npm --prefix web ci
```

Verify `command -v node`, `node -v`, and `npm -v` before regenerating browser locks or running frontend checks.

The explicit Conda lock is platform-specific and should not be treated as a cross-platform environment file. If a future dependency requires a different channel, Python minor version, package manager, browser runtime, or model download, ask the user before changing policy.
